# 跨 AI 交替与接续开发

[English](README.md)

让 Codex、Claude Code 以及未来其他 AI 工具能够接续同一项目：按可验证的工作单元开发，保留决策和授权，在切换窗口或额度不足时留下可恢复的现场。

## 核心做法

- 大任务先判断范围，再拆成可独立验证的工作单元。
- 平时写轻量检查点，切换时整理完整交接。
- 额度不足时先保留最低恢复信息，有余量才继续完成最小闭环。
- 接手人核对规范、交接、Git、代码和测试，不盲信旧摘要。
- 已授权工作可以继续；历史建议和路线图不自动成为新授权。
- 通用协议只维护一次，各项目复用已有文件建立映射。

这是工作流规则，不是自动调度服务；不会增加额度、自动同步工作树，也不能恢复从未保存的信息。

## 安装

将本仓库下载或克隆到普通目录，**不要直接放进工具的 skills 扫描目录**。使用 Python 3.10 或更新版本，在仓库目录执行：

```sh
python install.py --dry-run
python install.py --agent both
```

只安装一种工具可用 `--agent codex` 或 `--agent claude`。不需要第三方 Python 包。
已有不同入口不会自动覆盖；检查后可以用 `--replace-adapter`，脚本会先备份旧入口。
已有协议版本内容若不同则停止，不原地覆盖。自定义工具发现目录需手动放置适配入口。

安装后，Codex 的入口位于 `~/.agents/skills/alternating-agent-development/SKILL.md`，
CC 的入口位于 `~/.claude/skills/alternating-agent-development/SKILL.md`。
两者引用 `~/.agents/protocols/alternating-agent-development/releases/` 中的同一份版本化协议。
`~` 表示当前用户主目录。每种工具只有一个可发现入口；协议正文与模板放在扫描目录外，避免同名重复。

重新开一个工具会话后使用。项目固定版本优先于个人默认版本；换机器需要安装对应版本。

## 日常只需要这几句话

| 场景 | 提示词 |
|---|---|
| 接手已有工作 | 请接手开发工作。 |
| 普通交接 | 进入收尾/交接模式。 |
| 额度不足 | 额度不足，请进入收尾/交接模式。 |
| 首次接入项目 | 请用共享 skill 建立这个项目的接续规范。 |

需要显式调用时，Codex 使用 `$alternating-agent-development`，CC 使用 `/alternating-agent-development`。
自然语言是否自动命中取决于工具；项目的 AGENTS.md / CLAUDE.md 也可提供稳定入口。

两种收尾都会冻结扩展；额度不足时尤其优先保存中断位置与最后一次真实验证。
交接可以是部分完成或未验证，不能为了工作树干净而丢弃用户修改。

首次接入时先盘点项目已有规范、测试、决策与日志，再建立最小映射；不另造一套通用协议。
业务规则留在项目，接手人只在已有授权内继续。

欢迎通过 Issues 或 PR 提供失败复现、过度记录的例子、不同工具适配和改进建议。

```sh
python -m unittest discover -s tests -v
```
